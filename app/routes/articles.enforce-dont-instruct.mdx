*Enforce, don't instruct. Deterministic checks run before an agent's tool calls.*

A study put deterministic checks in front of an agent's tool calls. They were plain code that verified a rule before any write happened.

Task success: 29.6% → 42.0%.

They reran it on 750 new trials and got the same lift, within 0.1 points.

The interesting part is what the checks caught.

78% of failures were silent: a valid call, an accepted write, no error, and a final state that broke policy.

An agent that relies on error messages can't see that.

A human reading a plausible diff can't either.

A check that runs before the write can.

Two honest limits:

- It only works for rules you can decide mechanically. Judgement calls are out of scope.
- A check blocks; it doesn't repair. You get a visible stop instead of a silent failure. That's better, but it isn't success.

Meanwhile, fewer than 1% of agent configurations on GitHub declare any permission boundary.

Which of your "please don't" prompt rules could be a hard check instead?
