*"Almost right" is the expensive failure. Stack Overflow 2025, 31,000+ developers. The first causes the second.*

Obviously wrong code is cheap. You reject it in two seconds.

Almost-right code compiles. It reads plausibly. It might even pass the tests you have.

The only way to know it's wrong is to rebuild the intended behaviour in your head and compare. That's full comprehension — roughly the cost of writing it yourself.

Stack Overflow 2025, 31,000+ developers:

- 66% — top frustration: "almost right, but not quite"
- 45% — debugging AI code takes longer than writing it

Those aren't two separate complaints. The first one causes the second.

Further down the same list:

- 20% feel less confident in their own problem-solving
- 16% can't explain how the code works

That's the bill for accepting what you didn't fully verify.

Have you ever spent longer fixing an AI answer than it would've taken to write it?
